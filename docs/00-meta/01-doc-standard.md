# 文档规范

> 最后更新：2026-11-21（基线 v0.1.0）。

本文是 SessionNexus 文档体系的写作纪律。分层方式参考律匠仓库的文档中心：同一事实只在一层写全，其它地方只链接。导航见 [文档中心](../README.md)。

## 各层只写什么

| 层 | 只写什么 | 不写什么 |
|----|----------|----------|
| design/architecture | 产品边界、进程模型和接入方式 | 当天做到哪一步 |
| design/decisions | 已经采纳的交互和会话决策 | 安装步骤 |
| plans | 部分实现功能的边界、验收和待办 | 源码行号 |
| guide | 安装和运行 | 未实现能力写成已可用 |
| develop | 开发者怎么构建和测试 | 用户向的产品说明 |
| history/dev | 按日期归档的进度 | 现行规格的唯一副本 |
| meta | 文档规范 | 功能实现细节 |

本仓库不用 domain、reference、agent、releases 层，直到出现对应材料。

## 目录与编号

- 层目录使用 `NN-name/`。层内文档使用 `NN-name.md`，从 `01` 起。
- 每份文档只有一个一级标题。
- 活文档如果写「当前」，前 15 行要有日期。plans 与进度文档前 15 行写 `> 状态：已实现|部分实现|规划（YYYY-MM-DD，基线 vX.Y.Z）。`
- 链接用相对路径，不写绝对路径和行号。
- 不写账号、密钥和本机会话内容。
- 未实现的能力标成 `规划` 或 `部分实现`，不写成已经可用。代码与文档冲突时，以代码为准并改文档。
