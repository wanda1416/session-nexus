# 本地界面：群聊与按群隔离的会话

> 状态：部分实现（2026-11-21，基线 v0.1.0）。三栏界面、SQLite 和房间会话恢复已落地；浏览器扩展尚未在真实浏览器里验收。

界面按企业聊天软件来做。Agent 是联系人，话题是群。不做一个全局 Master Session。不同项目各开一个群，上下文留在这个群里。

这一版只设计本地桌面窗口。手机 API 以后复用同一套群和会话，不另做一套模型。

## 1. 页面

三栏。

| 栏 | 内容 |
|----|------|
| 左 | 上半是联系人，下半是群。联系人来自已配置的 Provider：Grok、Qoder、Codex、DSH。未安装的排在下面，标成不可用。 |
| 中 | 当前群的消息。底部输入框支持 `@` 点名。 |
| 右 | 本群成员，以及这个群里已经开出的工作会话：谁的、什么任务、Idle / Working / WaitingApproval / Finished。 |

没有「全部会话混在一个列表里」的主页。点一个联系人会打开和他的单聊，单聊就是只有一个成员的群，规则相同。

消息气泡按说话人区分：你、某个 Agent 的房间会话、某个 Agent 的工作会话。工作会话的气泡带任务标题，点开能看摘要，不把终端滚动刷进群。

## 2. 四个对象

```
联系人 Contact     = 一种 Agent（grok、qoder、dsh、codex）
群 Group           = 一个话题，例如「项目 A」
房间会话 Room      = 每个群里，每个成员恰好一个。只负责这个群的对话
工作会话 Work      = 房间会话通过我们的调度接口开出来的新会话。真正干活
```

房间会话和工作会话都是 Connector 上的原生会话（`claude`/`grok`/`qoder`/`dsh` 各自的 session）。区别是谁创建、注入什么、结果回到哪里。

| | 房间会话 | 工作会话 |
|--|----------|----------|
| 数量 | 每个（群，联系人）一个 | 一个任务一个，一个成员可以有多个 |
| 谁创建 | 拉人进群时，由我们创建 | 调度接口创建，不由 Agent 自己的 subagent 创建 |
| 注入 | 群的项目说明、成员名单、工作目录 | 项目说明，加上这一次的任务 |
| 说话 | 出现在群聊里，像这个联系人 | 进度和结果也发回这个群，挂在这个联系人下面 |
| 寿命 | 跟群走。换一个群就是另一套会话 | 任务结束就 Finished，不回收进别的群 |

所以「项目 A」里的 Grok 和「项目 B」里的 Grok 是两个房间会话。B 的讨论不会进 A。

## 3. 开群

1. 新建群，填写名称、工作目录、一段项目说明。例如：开发项目 A，仓库路径，要做的事。
2. 从联系人里拉人。例如 Grok、DSH、Qoder。
3. 每拉进一个人，调度接口为他创建一个房间会话，并写入同一份项目说明，外加一句约束：不要使用你自己的 subagent；需要干活时按下面的调度协议回复，由 SessionNexus 另开会话。

人可以后进群。后进的人只拿到当前项目说明，不重放别人的全部历史。用户也可以在群里发一条新的说明，我们把它追加进每个仍在群里的房间会话。

## 4. 在群里说话

- 输入 `@grok 你负责初始化项目`：只投递到这个群的 Grok 房间会话。
- 不带 `@` 的消息：投递到本群每一个房间会话。每个人用自己的会话理解，回复各自出现在群里。
- 房间会话的回复就是群里的一条消息，发送者显示为这个联系人。

房间会话如果认为要开工，它不自己拉 subagent。它在回复末尾给一段只给我们看的调度块，用户界面里收成一张「将要开工」的卡片：

```dispatch
{"task":"初始化项目","cwd":"D:/work/project-a"}
```

调度接口做这几件事：

1. 校验这个联系人属于这个群。
2. 用该联系人的 Connector 新建一个工作会话，不调用 `resume` 到房间会话上。
3. 注入项目说明和 `task`。
4. 在群里记下：Grok 开了工作会话「初始化项目」。
5. 工作会话的状态和结果摘要回到群里，并写一句短摘要回该成员的房间会话，让房间会话知道这件事已经交出去了。房间会话不接收工作会话的工具日志。

用户点卡片上的停止，只停这个工作会话。房间会话还在。

Grok、Qoder、DSH 各自的「子代理」功能不走这条路。房间会话的初始提示里写明禁止，调度只认我们的接口。

## 5. 单聊

单聊是只有一个联系人的群。同样有一个房间会话。`@` 可以省略，因为只有一个人。交代一个具体任务时，仍然开工作会话，避免把执行过程堆进这条长期对话。

## 6. 这一版界面做到哪

先做本地三栏，数据可以先放内存，下一步再进 SQLite。群、成员、两类会话的 id 要从第一天就分开存，避免以后把全局会话列表补回来。

先出现的联系人：Grok、Qoder、DSH、Codex。浏览器扩展不出现在联系人里，它是工作会话可以用的工具，不是一个会说话的成员。

这一版不做：全局 Master、把所有 Provider 会话铺成一个收件箱、在界面里嵌完整终端、手机布局。
